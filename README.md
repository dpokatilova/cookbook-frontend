# CookBook — Frontend
 
Фронтенд для платформи **CookBook**: сторінка зі списком рецептів, які завантажуються з Django REST API.
Можна відфільтрувати рецепти за категорією.
 
Бекенд: https://github.com/dpokatilova/cookbook
 
## Функціонал

### Сторінки

| Сторінка | Хто має доступ | Що там |
| --- | --- | --- |
| `index.html` | усі | список рецептів, фільтр за категорією |
| `login.html` | тільки неавторизовані | вхід |
| `register.html` | тільки неавторизовані | реєстрація |
| `add-recipe.html` | тільки авторизовані | форма додавання рецепта |

### Авторизація (JWT)

- Після логіну access і refresh токени зберігаються в `localStorage`.
- Кожен запит до захищених ендпоінтів передає заголовок `Authorization: Bearer <access>`.
- Access токен живе 5 хвилин. Коли він закінчується (сервер повертає 401), фронтенд автоматично отримує новий через `POST /users/token/refresh/` і повторює запит. Якщо refresh токен теж закінчився, користувача перенаправляє на логін.
- Logout видаляє обидва токени з `localStorage`.

### Поведінка

- Неавторизованого користувача, який відкриває `add-recipe.html`, перенаправляє на логін. Після входу його повертає на сторінку, з якої перенаправило (параметр `?next=`).
- Авторизованого користувача, який відкриває `login.html` або `register.html`, перенаправляє на головну.
- У шапці неавторизований бачить кнопки «Увійти» і «Реєстрація», авторизований — своє ім'я, «Додати рецепт» і «Вийти».
- Помилки валідації з бекенду показуються під відповідними полями форми.

### Структура скриптів

| Файл | Призначення |
| --- | --- |
| `auth.js` | спільний для всіх сторінок: робота з токенами, запити з автоматичним оновленням токена, захист сторінок, шапка |
| `script.js` | список рецептів на головній |
| `login.js`, `register.js`, `add-recipe.js` | логіка відповідних сторінок |

## Адреси та порти
 
| Частина | Адреса |
| --- | --- |
| Фронтенд | http://127.0.0.1:3000 |
| Бекенд (API) | http://127.0.0.1:8000 |
 
Адреса бекенду задана в `script.js` (константа `API_URL`).
Фронтенд запускається на іншому порту, тому на бекенді налаштований CORS: порт 3000 дозволений у `CORS_ALLOWED_ORIGINS`.
 
## Як запустити проєкт
 
1. Запустіть бекенд (інструкція в README бекенд-репозиторію), щоб API працював на `http://127.0.0.1:8000`.
2. Перейдіть у папку з фронтендом:
```bash
   cd cookbook-frontend
```
 
3. Запустіть простий вебсервер на порту 3000:
```bash
   python -m http.server 3000
```
 
4. Відкрийте в браузері http://127.0.0.1:3000
